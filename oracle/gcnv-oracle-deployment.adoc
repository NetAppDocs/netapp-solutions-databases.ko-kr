= Google Cloud NetApp Volumes 워크플로를 사용하여 고가용성 Oracle Database 26ai를 배포합니다.
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Google Cloud NetApp Volumes iSCSI 블록 스토리지를 사용하여 Google Compute Engine에 Oracle Data Guard가 포함된 고가용성 Oracle Database 26ai를 배포하세요. 이 워크플로는 배포 옵션, 인프라 프로비저닝, Oracle 소프트웨어 설치 및 고가용성 구성을 안내하며, GCNV의 스토리지 계층 복제를 활용하여 대기 서버 초기화 속도를 향상시킵니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["하나"]link:gcnv-oracle-solution-architecture.html["솔루션 아키텍처를 검토합니다."]
[role="quick-margin-para"]
Oracle Database 26ai의 고가용성을 위한 Google Cloud NetApp Volumes 아키텍처를 이해합니다. 여기에는 GCNV iSCSI 블록 스토리지 설계, Data Guard 통합 및 스토리지 토폴로지가 포함됩니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["둘"]link:gcnv-oracle-deployment-options.html["배포 옵션 및 요구 사항 검토"]
[role="quick-margin-para"]
개발/테스트 환경에서 프로덕션 고가용성(HA) 환경에 이르는 배포 단계를 비교하고, 인프라, 접근 권한 및 소프트웨어 관련 필수 요건을 확인하십시오.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["3"]link:gcnv-oracle-access-and-apis.html["액세스 및 API 확인"]
[role="quick-margin-para"]
필요한 액세스 권한, API 활성화, 네트워킹 전제 조건 및 시간 동기화를 확인하십시오.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["네"]link:gcnv-oracle-provision-compute.html["Google Compute Engine 인스턴스 프로비저닝"]
[role="quick-margin-para"]
주 데이터베이스, 대기 데이터베이스 및 Fast-Start Failover Observer용 VM을 생성합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["다섯"]link:gcnv-oracle-provision-storage.html["GCNV iSCSI 스토리지 프로비저닝"]
[role="quick-margin-para"]
GCNV 스토리지 풀과 iSCSI 볼륨을 생성하고, 다중 경로를 구성하며, ASM 디스크 그룹을 설정합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["6"]link:gcnv-oracle-install-software.html["Oracle Grid Infrastructure 및 Oracle Database 26ai 설치"]
[role="quick-margin-para"]
두 데이터베이스 호스트 모두에 Oracle Grid Infrastructure 및 Oracle Database 26ai 소프트웨어를 설치하십시오.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-7.png["일곱"]link:gcnv-oracle-primary-database.html["기본 데이터베이스를 생성합니다"]
[role="quick-margin-para"]
ASM 스토리지를 사용하는 기본 Oracle 데이터베이스를 생성하고 Oracle Restart를 구성합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-8.png["여덟"]link:gcnv-oracle-standby-database.html["대기 데이터베이스를 생성합니다"]
[role="quick-margin-para"]
GCNV 복제, 스냅샷 또는 클론을 사용하여 대기 데이터베이스를 초기화한 다음, Oracle Restart에 등록합니다. 모든 HA 계층에서 이 단계를 완료해야 합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-9.png["아홉"]link:gcnv-oracle-standby-finalize-dg.html["Data Guard용 대기 데이터베이스를 최종 확정합니다."]
[role="quick-margin-para"]
대기 리도 로그를 생성하고, 플래시백을 활성화하며, 리도 전송을 활성화하고, Data Guard 상태를 확인합니다. *계층별:* Prod HA(Data Guard + FSFO) 계층에서만 필요합니다.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-10.png["열"]link:gcnv-oracle-data-guard.html["Data Guard Broker 및 Fast-Start Failover 구성"]
[role="quick-margin-para"]
브로커를 활성화하고, Data Guard 구성을 생성하고, FSFO를 활성화하고, Observer를 구성합니다. *계층별:* Prod HA(Data Guard + FSFO) 계층에서만 필요합니다.
