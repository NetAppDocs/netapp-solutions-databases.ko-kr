[role="lead"]
Windows Server 2025에 SQL Server 2025를 배포하고, 사용자 데이터베이스, 트랜잭션 로그, TempDB 및 백업을 NetApp AFF 시스템의 SMB 3 상시 사용 가능 공유에 저장합니다. 이 절차에는 ONTAP SVM, 볼륨 및 공유 구성과 SQL Server 설치가 포함됩니다.



[[scope]]
[[intro-scope]]
== 범위

이 절차에서는 단일 Windows Server 2025 호스트에 독립 실행형 SQL Server 2025 인스턴스를 배포하고, 사용자 데이터베이스, 트랜잭션 로그, TempDB 및 백업을 SMB 3 지속적 가용성(CA) 공유에 저장합니다. 동일한 스토리지 설계는 SQL Server 장애 조치 클러스터 인스턴스(FCI) 및 Always On 가용성 그룹에도 적용되지만, 클러스터별 구성은 다루지 않습니다. SQL Server 성능 튜닝 및 크기 조정 또한 범위를 벗어납니다. 이점, 솔루션 구성 요소, 설계 원칙 및 지속적 가용성의 작동 방식에 대한 설명은 link:sql-smb3-aff-overview.html["SMB 3 지속적 가용성을 지원하는 NetApp AFF 기반 SQL Server 2025에 대해 알아보십시오"]을(를) 참조하십시오.



[[audience]]
[[intro-audience]]
== 대상

이 절차의 대상은 다음과 같습니다:

* ONTAP 클러스터, SVM, 볼륨 및 SMB 공유를 구성하는 *스토리지 관리자*.
* *Windows 및 Active Directory 관리자*, Windows Server 2025 호스트, 서비스 계정 및 네트워크를 준비합니다.
* *데이터베이스 관리자*는 SQL Server 2025를 설치 및 구성하고 백업 및 복구를 설정합니다.


ONTAP System Manager, Windows Server 및 SQL Server 관리에 대한 기본 지식이 있다고 가정합니다.

[cols="1,1,1,2"]
|===
| 볼륨 / 공유 | 크기 | UNC 경로 | 콘텐츠 


| `sql1_data` | 1024 GiB | `+\\a50-sql\sql1_data+` | 사용자 데이터베이스 데이터 파일 (`.mdf`, `.ndf`) 


| `sql1_log` | 512 GiB | `+\\a50-sql\sql1_log+` | 사용자 데이터베이스 트랜잭션 로그 파일 (`.ldf`)

[[prerequisites]]
== 필수 조건

시작하기 전에 다음 요구 사항을 충족하는지 확인하십시오:

.NetApp ONTAP
* AFF HA 페어가 설치되었고 클러스터가 설정되어 정상 작동합니다.
* CIFS(SMB) 라이선스가 설치되어 있습니다. ONTAP One에 포함되어 있습니다.
* 각 노드에는 최소한 하나의 데이터 애그리게이트(로컬 계층)가 존재합니다.
* 클러스터와 Active Directory 간의 시간은 NTP를 통해 동기화됩니다. Kerberos에 허용되는 최대 시간 차이는 5분입니다.
* SMB LIF용 데이터 네트워크 포트, 브로드캐스트 도메인 및 (선택적으로) VLAN이 구성됩니다.


.Active Directory 및 DNS
* Active Directory 도메인을 사용할 수 있으며, SVM 데이터 LIF에서 DNS 서버에 접근할 수 있습니다.
* CIFS 서버를 위해 대상 OU에 컴퓨터 객체를 생성할 수 있는 권한이 있는 계정이 있습니다.
* SQL Server 데이터베이스 엔진 및 SQL Server 에이전트 서비스의 서비스 계정으로 전용 도메인 사용자 계정을 사용할 수 있습니다.



IMPORTANT: SQL Server는 SMB 공유에 파일이 있는 경우 *도메인 계정*으로 실행되어야 합니다. 내장 가상 계정 (`NT SERVICE\MSSQLSERVER`) 및 로컬 계정에는 원격 파일 공유에 대한 액세스 권한을 부여할 수 없습니다.

.윈도우 서버
* Windows Server 2025(데스크톱 환경)가 설치, 패치 및 도메인 가입이 완료되었습니다.
* SQL Server 2025 설치 미디어(ISO)와 유효한 제품 키(또는 무료 버전)가 준비되어 있습니다.


.ONTAP의 SQL Server에 대한 SMB 요구사항 및 제한사항
* SVM에서 SMB 3.0 이상 버전이 활성화되어 있어야 합니다.
* CA 공유를 호스팅하는 모든 볼륨은 *NTFS* 보안 스타일을 사용해야 하며 처음부터 NTFS 형식이어야 합니다.
* SMB Direct(RDMA)는 지원되지 않습니다.
* ReFS는 지원되지 않습니다. ONTAP (WAFL)이 공유 폴더에 대한 파일 시스템을 제공합니다.

== 2단계: 스토리지 VM(SVM) 생성 및 구성

SQL Server에는 전용 SVM을 사용하십시오. SVM은 CIFS 서버로서 Active Directory에 조인하고 HA 쌍의 각 노드에 하나의 SMB 데이터 LIF를 제공합니다.

.단계
. System Manager 또는 CLI를 사용하여 SVM을 생성합니다:
+
[role="tabbed-block"]
====
.System Manager
--
.. System Manager에서 menu:Cluster[Storage VMs]로 이동하여 *+ 추가*를 클릭합니다.
+
.예제 표시
[%collapsible]
=====
image:sql25_smb_bp_006.png["클러스터 > 스토리지 VM > 추가"]

=====
.. *스토리지 VM 이름*을 입력합니다 `a50-sql`. *액세스 프로토콜*에서 *SMB/CIFS, NFS, S3* 탭을 선택하고 *SMB/CIFS 활성화*를 선택합니다.
+
.예제 표시
[%collapsible]
=====
image:sql25_smb_bp_007.png["스토리지 VM 추가 - 이름 및 프로토콜"]

=====
+

NOTE: 스토리지 VM 이름은 CIFS 서버의 SMB 이름입니다.

.. Active Directory 정보(도메인, 관리자 이름 및 암호, OU)와 DNS 정보(DNS 도메인 및 네임 서버)를 입력하십시오.
.. *네트워크 인터페이스*에서 *각* 노드에 데이터 LIF를 하나씩 구성하십시오.
+

TIP: 노드당 하나의 LIF를 사용하면 SQL Server가 각 노드에 대한 직접(로컬) 경로를 확보할 수 있으며, 이는 SMB 멀티채널 및 무중단 장애 조치를 위한 필수 조건입니다. 25 GbE 이상의 포트를 사용하고, 종단 간 동일한 MTU를 사용하십시오.

+

NOTE: 이러한 네트워크 인터페이스를 DNS 서버에 등록해야 합니다. 자세한 내용은  https://docs.netapp.com/us-en/ontap-system-manager-classic/smb-config/task_mapping_smb_server_dns_server.html["SMB 서버를 DNS 서버에 매핑합니다"^]을(를) 참조하십시오.

.. *저장*을 클릭합니다. System Manager는 SVM, 루트 볼륨, LIF 및 DNS 구성을 생성하고 CIFS 서버를 도메인에 가입시킵니다.
.. 랩 환경에서 SVM 루트 볼륨(`a50_sql_root`을 확인하십시오). 그렇지 않으면 SMB 공유가 작동하지 않으므로 *NTFS* 보안 스타일을 사용해야 합니다. menu:Storage[Volumes]로 이동하여 루트 볼륨을 선택하고 *Edit*를 클릭하여 설정을 검토하십시오.
+

--
.ONTAP CLI
--
다음 명령은 CLI에서 동일한 구성을 생성합니다. 꺾쇠괄호 안의 자리 표시자 값을 바꾸십시오.

[source, console]
----
cluster::> vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs

cluster::> vserver modify -vserver a50-sql -allowed-protocols cifs

cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

cluster::> vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>

cluster::> vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers
----
--
====
. [[svm-smb-options,SMB 서버 옵션 구성]]SMB 서버 옵션을 구성합니다. SQL Server에 필요한 SMB 옵션이 SVM에서 활성화되어 있는지 확인합니다:
+
[source, console]
----
cluster::> set -privilege advanced
cluster::*> vserver cifs options show -vserver a50-sql -fields smb3-enabled,is-multichannel-enabled,is-large-mtu-enabled,copy-offload-enabled,shadowcopy-enabled
cluster::*> vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
cluster::*> set -privilege admin
----
+
[cols="1,3"]
|===
| 옵션 | 목적 


| `smb3-enabled` | 지속적으로 사용 가능한 공유를 위해서는 SMB 3.x 버전이 필요합니다. 


| `is-multichannel-enabled` | SMB 멀티채널은 더 높은 처리량과 복원력을 위해 여러 개의 TCP 연결과 네트워크 경로를 사용합니다. 


| `is-large-mtu-enabled` | 최대 1MB의 SMB 읽기 및 쓰기를 허용합니다. 


| `copy-offload-enabled` | ODX 복사 오프로드; 복사는 스토리지 시스템 내부에서 수행됩니다. 


| `shadowcopy-enabled` | SMB 공유용 원격 VSS. SMB 공유에 VSS를 사용하는 백업 애플리케이션에 필요합니다. 
|===
. CIFS 서버가 DNS에 등록되어 있고 SQL Server 호스트에서 확인 가능한지 확인하십시오:
+
[source, powershell]
----
PS C:\> Resolve-DnsName a50-sql.sapcc.stl.netapp.com
----

.  `sql1_log`,  `sql1_tempdb` 및  `sql1_backups`에 대해 명령을 반복하십시오. 서비스 계정에는 공유 루트의 NTFS 권한에 대한 *모든 권한*도 필요합니다. SQL Server 설치 프로그램은 <<sql-dbengine>>에 표시된 것처럼 이를 확인합니다.

[[step-6-prepare-windows-server-2025]]
[[windows-prep]]
== 6단계: Windows Server 2025 준비

도메인 관리자 권한으로 SQL Server 호스트 `{host}`에서 다음 단계를 수행하십시오.

.단계
. 서버가 도메인에 가입되어 있고 CIFS 서버를 확인할 수 있는지 확인하십시오(<<svm-smb-options>> 참조).
. Active Directory에 SQL Server 서비스 계정이 있는지 확인하십시오(예:  `SAPCC\sql1admin`). Database Engine과 SQL Server Agent에 동일한 계정을 사용하거나 각각 별도의 계정을 사용하십시오. 어느 것을 선택하든 각 계정에 4개의 공유 모두에 대한 액세스 권한을 부여하십시오.
. 서비스 계정의 보안 컨텍스트에서 공유에 대한 액세스를 테스트합니다:
+
[source, powershell]
----
PS C:\> runas /user:SAPCC\sql1admin "cmd /c dir \\a50-sql\sql1_data && echo test > \\a50-sql\sql1_data\write-test.txt && del \\a50-sql\sql1_data\write-test.txt"
----
. Windows 방화벽에서 SQL Server 포트를 여십시오:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. SVM에 대한 SMB 연결을 확인하십시오. 다이얼렉트는 3.x여야 하며  `ContinuouslyAvailable`은(는)  `True`이어야 합니다:
+
[source, powershell]
----
PS C:\> dir \\a50-sql\sql1_data | Out-Null
PS C:\> Get-SmbConnection -ServerName a50-sql | Format-Table ServerName,ShareName,Dialect,ContinuouslyAvailable,Encrypted,Signed
PS C:\> Get-SmbMultichannelConnection -ServerName a50-sql
----



NOTE: Windows Server 2025는 기본적으로 모든 아웃바운드 SMB 연결에 대해 SMB 서명을 요구합니다. ONTAP은 SMB 서명을 지원하며 자동으로 협상합니다. 서명은 양쪽 모두에서 CPU 오버헤드를 발생시키므로 성능 테스트에 포함해야 합니다. 보안 검토 없이 서명을 비활성화하지 마십시오.

TIP: 논리적 CPU 코어당 하나의 TempDB 데이터 파일을 사용하며, 최대 8개까지 가능합니다. 초기 크기는 예상되는 TempDB 작업 세트 크기로 설정하여 TempDB가 작동 중에 크기를 늘릴 필요가 없도록 합니다. 모든 데이터 파일은 동일한 크기와 자동 증가 기능을 가져야 합니다.

+

NOTE: TempDB 데이터 파일 및 로그 파일용 폴더를 사용해야 합니다. 그렇지 않으면 설치가 실패합니다.

== 8단계: 설치를 확인하고 데이터베이스를 생성합니다

SQL Server Management Studio(SSMS)를 사용하여 테스트 데이터베이스를 생성하고 데이터 및 로그 파일이 SMB 공유에 있는지 확인합니다. 선택적으로 ONTAP에서 열려 있는 파일이 지속적인 가용성을 사용하는지 확인합니다.

.단계
. 설치 센터의 *SQL Server 관리 툴 설치* 링크 또는 Microsoft 웹사이트에서 SQL Server Management Studio(SSMS)를 설치하십시오.
. SSMS를 시작하고 Windows 인증을 사용하여 인스턴스 (`sql-1`)에 연결합니다.
. *데이터베이스*를 마우스 오른쪽 버튼으로 클릭하고 *새 데이터베이스...*를 선택합니다. 데이터베이스 이름을 입력하고((`SQ1` 실습의 경우), 초기 파일 크기를 설정한 다음 *확인*을 클릭합니다. 데이터 및 로그 파일 경로는 기본적으로  `+\\a50-sql\sql1_data+` 및  `+\\a50-sql\sql1_log+`(으)로 설정됩니다.
+
.예제 표시
[%collapsible]
====
image:sql25_smb_bp_047.png["UNC 경로를 사용하는 새 데이터베이스 대화 상자,width=800"]

====
. 새 데이터베이스가 *오브젝트 탐색기*에 나타납니다.

       type_desc,
       name AS logical_name,
       physical_name,

[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
== ONTAP CLI 스크립트를 사용하여 한 번에 스토리지를 구성하십시오

다음 스크립트에는 이 절차의 전체 스토리지 구성이 포함되어 있습니다. 실행하기 전에 꺾쇠괄호 안의 값을 바꾸십시오.

[source, console]
----
# --- SVM -----------------------------------------------------------------
vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs
vserver modify -vserver a50-sql -allowed-protocols cifs

network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>
vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers

set -privilege advanced
vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
set -privilege admin

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql1_data    -aggregate <aggr_node1> -size 1TB   -security-style ntfs -junction-path /sql1_data    -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
volume create -vserver a50-sql -volume sql1_log     -aggregate <aggr_node2> -size 512GB -security-style ntfs -junction-path /sql1_log     -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_tempdb  -aggregate <aggr_node2> -size 500GB -security-style ntfs -junction-path /sql1_tempdb  -space-guarantee none -percent-snapshot-space 0 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_backups -aggregate <aggr_node1> -size 2000GB -security-style ntfs -junction-path /sql1_backups -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 2600GB

# --- CA shares -----------------------------------------------------------
vserver cifs share create -vserver a50-sql -share-name sql1_data    -path /sql1_data    -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_log     -path /sql1_log     -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_tempdb  -path /sql1_tempdb  -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_backups -path /sql1_backups -share-properties oplocks,browsable,changenotify,continuously-available

# --- Share permissions (repeat for each share) ----------------------------
vserver cifs share access-control create -vserver a50-sql -share sql1_data -user-or-group SAPCC\sql1admin -permission Full_Control
vserver cifs share access-control delete -vserver a50-sql -share sql1_data -user-or-group Everyone

# --- Verification ----------------------------------------------------------
vserver cifs show -vserver a50-sql
vserver cifs share show -vserver a50-sql -fields share-name,path,share-properties
vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----

TIP: 예를 들어 데이터와 백업은 노드 1에, 로그와 TempDB는 노드 2에 저장하는 식으로 볼륨을 두 노드의 애그리게이트에 분산합니다. 이렇게 하면 두 컨트롤러의 리소스를 모두 활용할 수 있습니다.
