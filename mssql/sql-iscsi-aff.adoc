= iSCSI LUN을 사용하여 NetApp AFF에 SQL Server 2025 배포
:allow-uri-read: 


[role="lead"]
NetApp AFF 시스템의 iSCSI LUN에 사용자 데이터베이스, 트랜잭션 로그, TempDB 및 로그 백업을 배치하여 Windows Server 2025에 SQL Server 2025를 배포합니다. 이 절차에는 ONTAP SVM, 이니시에이터 그룹 및 LUN, Windows iSCSI 이니시에이터, MPIO 및 디스크에 대한 iSCSI 구성과 SQL Server 설치가 포함됩니다.



[[scope]]
[[intro-scope]]
== 범위

이 절차에서는 단일 Windows Server 2025 호스트에 독립 실행형 SQL Server 2025 인스턴스를 배포하고, 사용자 데이터베이스, 트랜잭션 로그, TempDB 및 로그 백업을 iSCSI LUN에 저장합니다. 동일한 스토리지 설계는 SQL Server 장애 조치 클러스터 인스턴스(FCI) 및 Always On 가용성 그룹에도 적용되지만, 클러스터별 구성은 다루지 않습니다. SQL Server 성능 튜닝 및 크기 조정 또한 이 절차의 범위를 벗어납니다. 이점, 솔루션 구성 요소, 설계 원칙, 다중 경로 작동 방식에 대한 설명 및 NetApp Console 백업 및 복구를 사용한 데이터 보호에 대한 자세한 내용은 link:sql-iscsi-aff-overview.html["iSCSI LUN을 사용하는 NetApp AFF의 SQL Server 2025에 대해 알아보십시오."]를 참조하십시오.



[[audience]]
[[intro-audience]]
== 대상

이 절차의 대상은 다음과 같습니다:

* ONTAP 클러스터, SVM, iSCSI LIF, 이니시에이터 그룹 및 LUN을 구성하는 *스토리지 관리자*.
* Windows Server 2025 호스트, iSCSI 이니시에이터, MPIO 및 디스크를 준비하는 *Windows 관리자*.
* *데이터베이스 관리자*는 SQL Server 2025를 설치 및 구성하고 백업 및 복구를 설정합니다.


ONTAP System Manager, Windows Server 및 SQL Server 관리에 대한 기본 지식이 있다고 가정합니다.

[[overview]]
== 랩 환경

[cols="1,2"]
|===
| 구성 요소 | 실험실에서 사용된 값 


| 스토리지 시스템 | NetApp AFF A50 HA 페어, 클러스터 `{cluster}` (노드 `{node1}`, `{node2}`), ONTAP 9.19.1 


| SVM | `{svm}` 


| iSCSI 타겟 이름 | `{tgt-iqn}` (별칭 `{svm}`) 


| iSCSI LIF | 192.168.175.134 및 192.168.175.135(노드 `{node1}`), 192.168.175.136 및 192.168.175.137(노드 `{node2}`), 서브넷 /24, 브로드캐스트 도메인 `MT9000` 


| Active Directory 도메인 | `{domain}` (`{fqdn-domain}`) 


| SQL Server 호스트 | `{host}.{fqdn-domain}`, Windows Server 2025 Datacenter(데스크톱 환경) 


| 호스트 iSCSI 이니시에이터 | `{init-iqn}`, iSCSI IP 주소 192.168.175.44 


| 이니시에이터 그룹 | `{igroup}`, 호스트 OS *Windows* 


| SQL 서버 | SQL Server 2025 Enterprise Edition, 기본 인스턴스 `MSSQLSERVER` 
|===
[cols="2,2,1,1,2"]
|===
| LUN | 볼륨 | 크기 | 드라이브 | 콘텐츠 


| `sql_iscsi_1_data_1` | `sql_iscsi_1_data` | 520 GiB | `E:` (데이터) | 사용자 데이터베이스 데이터 파일 (`.mdf`, `.ndf`) 위치: `E:\data` 


| `sql_iscsi_1_log_1` | `sql_iscsi_1_log` | 250 GiB | `F:` (로그) | 사용자 데이터베이스 트랜잭션 로그 파일 (`.ldf`) in `F:\log` 


| `sql_iscsi_1_tempdb_1` | `sql_iscsi_1_tempdb` | 150 GiB | `G:` (tempdb) |  `G:\tempdb\data` 및  `G:\tempdb\log`의 TempDB 데이터 및 로그 파일 


| `sql_iscsi_1_logbackup_1` | `sql_iscsi_1_logbackup` | 300 GiB | `H:` (로그 백업) | 네이티브 SQL Server 백업 파일 (`.bak`, `.trn`) 내 `H:\backup` 
|===

TIP: 볼륨당 하나의 LUN을 사용하고 데이터, 로그, TempDB 및 백업용으로 볼륨을 분리하십시오. 이렇게 하면 볼륨별로 서로 다른 QoS, 스냅샷, 효율성 및 복제 설정을 적용할 수 있습니다. 또한 지속적으로 변경되는 TempDB를 사용자 데이터베이스의 스냅샷에서 제외할 수 있습니다.


TIP: 부하를 분산하려면 추가 보조 데이터 파일(.ndf)을 위해 다른 컨트롤러의 추가 LUN을 사용하십시오.



[[prerequisites]]
== 필수 조건

시작하기 전에 다음 요구 사항을 충족하는지 확인하십시오:

.NetApp ONTAP
* AFF HA 페어가 설치되었고 클러스터가 설정되어 정상 작동합니다.
* iSCSI 라이센스가 설치되어 있습니다. ONTAP One에 포함되어 있습니다.
* 각 노드에는 최소한 하나의 데이터 애그리게이트(로컬 계층)가 존재합니다.
* SVM이 존재합니다. 이 절차에서는 기존 SVM `{svm}`을 사용하며, 여기에 iSCSI를 추가합니다. SAN 전용 SVM을 생성하려면 menu:Cluster[Storage VMs > Add]를 사용하고 *iSCSI*를 액세스 프로토콜로 선택합니다.
* iSCSI LIF용 데이터 네트워크 포트, 브로드캐스트 도메인 및 (선택적으로) VLAN이 구성됩니다. 실습 환경에서는 브로드캐스트 도메인 `MT9000`이 점보 프레임을 사용합니다.
* 클러스터, 호스트 및 Active Directory 간의 시간은 NTP를 통해 동기화됩니다.


.네트워크
* SQL Server 호스트에는 iSCSI 서브넷 또는 VLAN에 iSCSI 전용 NIC가 하나 이상, 가급적 두 개 이상 있어야 합니다.
* MTU는 종단 간(호스트 NIC, 스위치, ONTAP 포트) 동일합니다. 호스트에서  `ping -f -l 8972 <LIF-IP>`(으)로 점보 프레임을 확인하십시오.


.윈도우 서버
* Windows Server 2025(데스크톱 환경)가 설치, 패치 및 도메인 가입이 완료되었습니다.
* Windows Server 2025에서 지원되는 버전의 NetApp Windows 호스트 유틸리티를 사용할 수 있습니다( https://imt.netapp.com/matrix/["NetApp 상호 운용성 매트릭스 툴(IMT)"^] 참조).
* SQL Server 2025 설치 미디어(ISO)와 유효한 제품 키(또는 무료 버전)가 준비되어 있습니다.



NOTE: SMB 파일 공유와 달리 LUN은 SQL Server 서비스에 도메인 계정이 필요하지 않습니다. 기본 가상 계정 (`NT Service\MSSQLSERVER`)을 사용할 수 있습니다. 예를 들어 파일 공유에 백업하거나 Kerberos 인증을 위해 인스턴스에 네트워크 액세스가 필요한 경우에는 여전히 도메인 계정 또는 gMSA를 사용하는 것이 좋습니다.

== 1단계: 스토리지 VM에서 iSCSI를 활성화합니다

SVM에 iSCSI 프로토콜을 추가하고 HA 쌍의 각 노드에 두 개의 iSCSI LIF를 생성합니다.

.단계
. SVM에서 iSCSI를 활성화하고 System Manager 또는 CLI를 사용하여 iSCSI LIF를 생성합니다:
+
[role="tabbed-block"]
====
.System Manager
--
.. 웹 브라우저를 열고  `+https://<cluster-management-IP>+`에서 ONTAP System Manager에 접속하십시오. 클러스터 관리자 계정으로 로그인하십시오.
.. menu:Cluster[Storage VMs]로 이동하여 SVM `{svm}`을 클릭하고 *설정* 탭을 엽니다. *프로토콜* 아래의 *iSCSI* 타일에 *구성되지 않음*이 표시됩니다. *iSCSI* 타일의 톱니바퀴 아이콘을 클릭합니다.
+
.예제 표시
[%collapsible]
=====
image:sql25_iscsi_bp_004.png["iSCSI가 구성되지 않은 스토리지 VM a50-sql 설정,width=800"]

=====
.. *iSCSI 구성* 대화 상자에서 iSCSI 네트워크 인터페이스를 생성합니다. System Manager는 노드당 두 개의 네트워크 인터페이스를 권장합니다. 다음 값을 입력하십시오.
+
*** 노드 `{node1}`: IP 주소 `192.168.175.134`, 서브넷 마스크 `24`, *브로드캐스트 도메인 및 포트* `MT9000`
*** *다음 모든 인터페이스에 동일한 서브넷 마스크, 게이트웨이 및 브로드캐스트 도메인 사용*을 선택하십시오.
***  `{node1}`의 두 번째 인터페이스: `192.168.175.135`
*** 노드 `{node2}`: `192.168.175.136` 및 `192.168.175.137`
+
*저장*을 클릭합니다.

+

TIP: 호스트와 LIF가 동일한 서브넷에 있는 경우 게이트웨이가 필요하지 않습니다. iSCSI 트래픽을 라우팅하지 마십시오.

--
.ONTAP CLI
--
다음 명령은 CLI에서 동일한 구성을 생성합니다. 꺾쇠괄호 안의 자리 표시자 값을 바꾸십시오.  `vserver iscsi show`의 출력에서 대상 이름을 확인하십시오. 호스트에서 연결을 확인하려면 이 이름이 필요합니다.

[source, console]
----
cluster::> vserver add-protocols -vserver a50-sql -protocols iscsi
cluster::> vserver iscsi create -vserver a50-sql -target-alias a50-sql

cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

cluster::> vserver iscsi show -vserver a50-sql
cluster::> network interface show -vserver a50-sql -data-protocol iscsi
----
--
====



NOTE: iSCSI LIF는 테이크오버 중에 마이그레이션되지 않습니다. 고가용성은 파트너 노드의 LIF 경로를 통해 제공되므로 HA 쌍의 두 노드 모두에 항상 iSCSI LIF를 생성해야 합니다.

== 2단계: Windows 호스트 준비

Microsoft iSCSI 이니시에이터를 시작하고 MPIO 및 NetApp Windows 호스트 유틸리티를 설치합니다. 로컬 관리자로서 SQL Server 호스트 `{host}`에서 다음 단계를 수행합니다.


IMPORTANT: LUN에 연결하기 *전에* MPIO를 설치하고 구성하십시오. MPIO가 없으면 Windows는 각 LUN에 대한 경로마다 디스크 하나씩을 표시합니다(이 구성에서는 LUN당 4개의 디스크).

.단계

+
[role="tabbed-block"]
====
.서버 관리자
--
.. *서버 관리자*에서 menu:툴[iSCSI 이니시에이터]를 엽니다.

.PowerShell
--
마지막 명령은 이니시에이터 이름을 반환합니다. ONTAP에서 이니시에이터 그룹을 생성하려면 이 이름이 필요합니다.

[source, powershell]
----
PS C:\> Set-Service -Name MSiSCSI -StartupType Automatic
PS C:\> Start-Service -Name MSiSCSI
PS C:\> (Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress
----
--
====

====

+

+
다시 시작한 후 확인란이 선택되고 회색으로 표시됩니다. 이는 MPIO가 모든 iSCSI 장치를 클레임함을 의미합니다. LUN이 연결된 후(<<connect>> 참조),  `Get-Disk`은(는) PowerShell 창에 표시된 것처럼 각 NetApp LUN을 한 번씩만 나열합니다.

[[step-5-review-the-volume-and-lun-settings]]
[[volume-settings]]
== 5단계: 볼륨 및 LUN 설정을 검토합니다

네 개의 볼륨에 대한 공간 및 스냅샷 설정을 검토하십시오. System Manager는 적절한 기본값을 사용하며, SQL Server LUN의 경우 다음과 같은 설정을 권장합니다.

[cols="1,1,3"]
|===
| 환경 | 가치 | 이유 


| 공간 보장(볼륨) | `none` (씬) | 용량은 데이터가 기록될 때만 소모됩니다. 


| LUN 공간 예약 | `disabled` (씬) | 씬 볼륨의 씬 LUN. 


| LUN 공간 할당 | `enabled` | SCSI UNMAP을 활성화하여 NTFS에서 해제된 공간이 ONTAP으로 반환되도록 하고, 볼륨의 공간이 부족할 때 호스트가 올바르게 대응할 수 있도록 합니다. 


| 스냅샷 정책 | `none` | 애플리케이션 정합성이 보장되지 않는 스냅샷은 SQL Server에 사용할 수 없습니다. 백업은 NetApp Console 백업 및 복구를 통해 생성됩니다. 


| 스냅샷 예약 | `0` % | 스냅샷 공간은 대신 볼륨 자동 크기 조정으로 모니터링됩니다. 


| 자동 크기 조정 | `grow`, 볼륨 크기의 최대 약 130% | 스냅샷이 공간을 차지할 때 LUN이 오프라인 상태가 되는 것을 방지합니다. 


| 스토리지 효율성 | 활성화됨(AFF에서 기본값) | 인라인 중복 제거, 압축 및 컴팩션은 SQL Server 성능에 측정 가능한 영향을 미치지 않습니다. 
|===
다음 명령을 사용하여 설정을 적용하고 확인하십시오( `sql_iscsi_1_data`에 대해 표시됨):

[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

NOTE: 기존 LUN에서  `space-allocation`을(를) 변경하려면 LUN이 오프라인 상태여야 합니다. 생성 시 또는 호스트가 LUN에 연결하기 전에 설정하십시오.

| 디스크 2 | 250 GB | `F:` | `log` 


| 디스크 3 | 150 GB | `G:` | `tempdb` 


| 디스크 4 | 300 GB | `H:` | `Log backup` 
|===
.. SQL Server용 폴더를 생성합니다: `E:\data`, `F:\log`, `G:\tempdb\data`, `G:\tempdb\log` 및  `H:\backup`.


--
.PowerShell
--
다음 명령은 NetApp 디스크를 온라인 상태로 만들고, GPT로 초기화하고, 각 디스크에 64K 할당 단위 크기의 NTFS 볼륨을 하나씩 생성 및 포맷하고, SQL Server용 폴더를 생성합니다.

[source, powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----

CAUTION: 이 LUN이 시스템에 연결된 유일한 RAW LUN인 경우에만 이 명령을 실행하십시오. 시스템에 다른 RAW LUN이 연결되어 있는 경우, 폴더를 수동으로 생성하고 볼륨을 포맷해야 합니다.

--

== 9단계: 설치를 확인합니다

테스트 데이터베이스를 생성하고, 해당 데이터베이스의 데이터 및 로그 파일이 NetApp LUN에 있는지, 그리고 스토리지 경로가 정상인지 확인합니다.

.단계
. Windows 방화벽에서 SQL Server 포트를 여십시오:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. 설치 센터의 *SQL Server 관리 툴 설치* 링크 또는 Microsoft 웹사이트에서 SQL Server Management Studio(SSMS)를 설치하십시오.
. SSMS를 시작하고 Windows 인증을 사용하여 인스턴스(`{host}`)에 연결합니다. 테스트 데이터베이스를 생성합니다. 해당 데이터 및 로그 파일은 기본적으로  `E:\data` 및  `F:\log`에 저장됩니다.
. T-SQL을 사용하여 파일 위치를 확인하십시오:
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----
. 즉시 파일 초기화가 활성화되어 있는지 확인하십시오:
+
[source, sql]
----
SELECT servicename, service_account, instant_file_initialization_enabled
FROM   sys.dm_server_services;
----
. 호스트 및 ONTAP에서 스토리지를 확인합니다:
+
[source, powershell]
----
PS C:\> Get-Disk | Where-Object FriendlyName -like 'NETAPP*' | Format-Table Number,FriendlyName,Size,OperationalStatus,PartitionStyle
PS C:\> mpclaim -s -d
----
+
[source, console]
----
cluster::> lun show -vserver a50-sql -fields path,size,mapped,state
cluster::> vserver iscsi session show -vserver a50-sql
cluster::> qos statistics volume latency show -vserver a50-sql
----
. 선택 사항: 고가용성을 테스트합니다. 테스트 데이터베이스에 대해 워크로드를 실행하고 데이터 볼륨을 소유한 노드의 ONTAP 테이크오버 및 기브백을 수행합니다 (`storage failover takeover -ofnode <node>` / `storage failover giveback -ofnode <node>`). 워크로드는 몇 초간 일시 중지되었다가 다시 시작되며 데이터베이스는 온라인 상태를 유지합니다.


.다음 단계
애플리케이션 정합성 보장 스냅샷 백업으로 데이터베이스를 보호하십시오. 아키텍처, 백업 워크플로 및 이점에 대해서는 link:sql-iscsi-aff-overview.html#console["NetApp Console 백업 및 복구를 통한 데이터 보호"]을 참조하십시오.

== ONTAP CLI 스크립트를 사용하여 한 번에 스토리지를 구성하십시오

다음 스크립트에는 이 절차의 전체 스토리지 구성이 포함되어 있습니다. 실행하기 전에 꺾쇠괄호 안의 값을 바꾸십시오.

[source, console]
----
# --- iSCSI service and LIFs ----------------------------------------------
vserver add-protocols -vserver a50-sql -protocols iscsi
vserver iscsi create -vserver a50-sql -target-alias a50-sql

network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

# --- Initiator group -----------------------------------------------------
lun igroup create -vserver a50-sql -igroup sql-iscsi-1 -protocol iscsi -ostype windows -initiator iqn.1991-05.com.microsoft:sql-iscsi-1.sapcc.stl.netapp.com

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql_iscsi_1_data      -aggregate <aggr_node1> -size 560GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
volume create -vserver a50-sql -volume sql_iscsi_1_log       -aggregate <aggr_node2> -size 270GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 350GB
volume create -vserver a50-sql -volume sql_iscsi_1_tempdb    -aggregate <aggr_node2> -size 165GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 210GB
volume create -vserver a50-sql -volume sql_iscsi_1_logbackup -aggregate <aggr_node1> -size 325GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 420GB

# --- LUNs ----------------------------------------------------------------
lun create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -size 520GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -size 250GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -size 150GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -size 300GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled

# --- LUN mapping ---------------------------------------------------------
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -igroup sql-iscsi-1

# --- Verification ----------------------------------------------------------
vserver iscsi show -vserver a50-sql
network interface show -vserver a50-sql -data-protocol iscsi
lun show -vserver a50-sql -fields path,size,ostype,space-allocation,mapped,state
lun mapping show -vserver a50-sql
vserver iscsi session show -vserver a50-sql
----

TIP: 예를 들어 데이터 및 로그 백업은 노드 1에, 로그 및 TempDB는 노드 2에 저장하는 등 두 노드의 애그리게이트에 볼륨을 분산합니다. 이렇게 하면 두 컨트롤러의 리소스를 모두 활용할 수 있습니다.

[[ps-script]]
== PowerShell 스크립트를 사용하여 호스트를 한 번에 구성하십시오

다음 스크립트에는 이 절차에 따른 전체 호스트 구성이 포함되어 있습니다. 관리자 권한 PowerShell 세션에서 실행하십시오. MPIO 부분은 재시작이 필요합니다.

[source, powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

NOTE: 각 부분을 별도로 실행하십시오. 파트 1은 호스트를 재부팅해야 하므로 재부팅 후에는 나머지 부분이 진행되지 않습니다.


CAUTION: 이 LUN들이 시스템에 연결된 유일한 RAW LUN인 경우에만 3부의 명령을 실행하십시오. 시스템에 다른 RAW LUN이 연결되어 있는 경우, 폴더를 수동으로 생성하고 볼륨을 포맷해야 합니다.
